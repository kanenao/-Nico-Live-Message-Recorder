# アプリ内報告受付（開発候補）
このPRは受付サービスを未公開のまま完成扱いにしない。既定の受付URLは未設定。
- Node.js 22で `FEEDBACK_GITHUB_TOKEN=... node server/feedback-relay.cjs` を実行する。トークンはサーバーの秘密情報として管理し、対象リポジトリのIssues書き込みのみに限定する。GitHub Actionsの分類を起動できる認証方式を使う（GITHUB_TOKENでは後続のissuesイベントが抑止される）。
- 公開する前にHTTPSリバースプロキシ、クライアント別レート制限、ボット対策、タイムアウト、アクセスログの個人情報最小化、監視を設定する。現実装は単一プロセス内の全体制限と24時間重複抑止のみ。再起動時の重複抑止と障害時の永続受付は未実装。
- HTTPSの /feedback URLをデプロイ後にpackage.jsonのfeedbackEndpointへ設定し、β版で検証する。開発時はNICO_FEEDBACK_ENDPOINTを利用できる。認証情報をアプリに設定しない。
- 実際の受付番号・GitHub Issue・AI分類ワークフローの結果・再試行・失敗時の入力保持を確認する。報告は公開Issueになる。個人情報や認証情報を入力しないことを明示し、既存の検査は完全ではないことに留意する。
- 自動修正は既存の日次開発タスクが担当。報告の内容は信頼できない入力として扱い、修正PRとCIを経る。正規版は原則月次保守。
- URL未設定の現状は送信できないため、実デプロイと検証が完了するまでマージ・配布しない。
