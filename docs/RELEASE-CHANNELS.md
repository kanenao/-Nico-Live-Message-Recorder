# β版・製品版リリース運用

## ブランチ

- `beta`: 日常の開発ブランチ。機能追加・修正を先行して実施する。
- `stable`: 製品版専用ブランチ。β版の検証を通過した変更だけを選んで取り込む。初回の製品版候補が承認できるまで作成しない。
- `main`: 移行前の履歴を保持するブランチ。新規開発は `beta` で行う。

## β版の公開条件

1. `beta` への変更でWindowsビルドワークフローを実行する。
2. `npm test` が成功すること。
3. WindowsインストーラーとZIPのビルドが成功すること。
4. βバージョン（例: `0.1.0-beta.68`）のみ、GitHub Releasesのbetaチャンネルへ公開する。

CI成功は実機での録画成功を意味しない。実機確認結果は別途記録する。

## 製品版の公開条件

- 重大・高優先度の不具合が未解決でないこと。
- 接続、映像・音声録画、コメント取得、停止、ファイル確定、再起動後の保存ファイル確認をWindows実機で実施すること。
- AI記事生成、Whisper/Ollamaの未設定時フォールバック、既存データの読み込みを確認すること。
- β版で発生した不具合と修正内容を確認し、未解決事項をリリースノートへ明記すること。
- 製品版専用の更新メタデータ（latestチャンネル）を生成し、β版の自動更新フィードと分離すること。

## バージョンと配布

- β版: `0.1.0-beta.N`、GitHub prerelease、beta更新チャンネル。
- 製品版: `1.0.0` 以降、正式Release、latest更新チャンネル。
- β版の更新が製品版ユーザーへ配信されないことを、公開前に更新メタデータと配布物で確認する。
- 製品版の更新がβ版ユーザーへ誤配信されないことも確認する。

## 重要

自動テスト成功だけで「不具合がない」と断定しない。実機確認・既知の問題・復旧手順を確認し、リリース担当者が製品版への昇格を判断する。
